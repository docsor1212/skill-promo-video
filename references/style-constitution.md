# 风格宪法（STYLE CONSTITUTION）——推广视频的成败判据

> 何时读我: 制作任何推广视频前必读; 返工争论时以本文为裁决依据。
> 来源: aesthete-agent 推广视频生产实战（10-18/10-19 两日，v1-v11 十一次迭代，用户逐帧裁决沉淀）。
> 效力: P0 铁律一票否决; 违反任何一条=整段重做。

## 一、目标（写给谁看）

- 60-120s 竖直叙事：封面(3-6s 有解说) → 开场口播 → N×[口播段 → 教程卡 → 图页] → 收尾口播 → 背书卡 → 片尾卡(含安装方式)。
- 受众最大化：不绑定单一场景词汇（如"写页面"），覆盖"用 AI 做东西的所有人"（页面/图表/幻灯/封面）。
- 观看效果判据：**看完就知道 skill 是干什么的、能帮自己干什么、并且想去下载体验**。
- 解说从封面第一秒就开始（封面不静音），并**念出 skill 名称**（名称含英文时预算 +1.5s）。

## 二、文字场景纪律（P0——历史上三次翻车的重灾区）

1. **带文字的场景（封面/教程卡/背书卡/片尾卡）唯一合法做法 = PE 一次成栈**（hope11 配方）：
   场景+人物+笔刷横幅+全部文字在一次 PE 生成里完成；TEXTZONE 逐项列文字 +
   CHECK 逐字核对清单（含英文字母逐字拼写）；出图必过 tesseract OCR + 人工目检双验。
2. ⛔ 三条已证伪路线，永不复用：
   - PIL 素排版做封面/文字页（普通字体丑、无渲染力——用户否）；
   - face_paste 面部窗口贴回（鬼脸——用户否）；
   - 教程卡整卡走 H3 动画（文字融化/构图漂移——pitfalls #34）。
3. **图页例外**：图页必须承载真实截图/真实图表（真实性闸门，见第四节），
   用 PIL 做挂轴卷轴家族风版式：木轴 + 宣纸底 + 金边截图 + 红幅笔刷标题 +
   霞鹜文楷正文（字体=/home/ubsea/.local/share/fonts/LXGWWenKai-Regular.ttf）。
4. 封面/片尾 ⛔ 版本号；笔刷横幅上的文字逐字核对后仍需目检（毛笔/手写体 OCR 会漏，视觉为准）。

## 三、人物纪律（P0）

1. **中近景或特写**（胸部以上入画，面部占画面 ≥1/3）——人物太小=身份漂移+无感染力。
2. **表情丰富**：惊喜开扬/浅笑温和/眼神有光，⛔严肃呆立、⛔正襟危坐。
3. **动作自然有渲染力**：掌心向上展示手势、头微偏、肩线自然错落、讲解时抬手示意。
4. **双手不拿任何物品**（持卷/持物=易画错），手上无物时逐指清点仍为一票否决项。
5. 口播段提示词：**同步句前置**——"her lip movements match <Audio 1> exactly" 必须放在
   提示词最前（注意力优先），其后才是放松体态/镜头描述（talking_segment 会恒定追加该句，
   但位置在后；scene_prompt 里自己再写一遍双保险）。

## 四、环境纪律（P0）

1. ⛔ 蜡烛、烛台及一切火焰元素（本次实战后新增）。
2. ⛔ 与内容场景无关的元素（道具、装饰、与主题无关的陈设）。
3. 场景贴合内容主题；背景虚化、深色沉稳或素雅纸感，为文字区让位。

## 五、文案纪律（P0）

1. **真人白话**：解说与卡片文字全用结果导向的自然语言，念出来像人话。
   ⛔ 行话缩写（WCAG/APCA/60-30-10）、⛔规格罗列（测试数/平台数/版本号）、⛔AI 腔（赋能/极致/所见即所交付）。
2. 案例气泡 = 用户会对智能体说的原话（如"给我钱包应用配个色，要素雅，别太花"）。
3. 封面标题句式 = 一眼懂的结果句（AF 例："论文配图 一键生成"；aesthete 例："一句话 页面变好看"）。
4. 旁白长度 ≤ 段窗（口播段≤5.1s 走 H3；名称含英文时预算 +1.5s）。

## 六、真实性闸门（P0）

1. 每个案例的链路 **用户请求 → 引擎命令 → 页面结果** 必须用引擎真跑验证：
   图页注脚的每个数字（打分/比值/检查结论）必须与页面徽章同板同源、引擎实测。
2. ⛔ 引用未验证的色板名/打分/比值（历史上 Lavender/Deep Space Blue 错标事故）。
3. demo 案例选型先过「AI 默认丑配色」关：荧光粉紫/电紫/高饱撞色 = 反面教材；
   "鲜艳"的合法形态 = 有品位的鲜活；素雅 ≠ 寡淡（层次完整）。
4. 现成场景不达标时，**用 skill 本尊现做一个**（visualize/report 直出），这是最强 dogfood。

## 七、质控闸门（全部通过才可交付）

| # | 闸门 | 工具 | 判据 |
|---|---|---|---|
| 1 | 逐字 OCR | tesseract + 放大目检 | 笔刷字体 OCR 弱读，疑字必须放大人审 |
| 2 | 手部逐指 | qc_gates hands + 裁片放大 | 多指/并指=一票否决 |
| 3 | 口型对齐 | measure_sync.py 互相关 | 逐段实测偏移写入 onsets.json，注入补偿 |
| 4 | 全轨听写 | delivery_gate.py --require/--forbid | 词表必须随当期解说词同步更新 |
| 5 | 抽帧目检 | ffmpeg + 人工 | 覆盖每类页面至少一帧 |

- 口型偏移测量必须用**互相关法**（唇动曲线×音频能量包络求最优滞后）；
  阈值 onset 法会被呼吸/起势运动污染误测为 0。实测偏移 0.04-0.46s 逐段不同。
- 旁白 wav 比段长 = 溢出进下一段与下段旁白同播（"两个人的声音"）——
  装配器必须断言旁白尾 ≤ 段尾，超了加长页面或缩短文案。
- 页面下部有漆字的页面（封面等），该段字幕置空（subs[id]=" "）防 ASS 字幕碰撞。
- 交付文件命名用清晰中文名（⛔内部版本号 v2/v4/v6——用户会误以为没更新）。
